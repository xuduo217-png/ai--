# Admin 公开隐私政策页面设计

## 目标

在 Admin 部署域名下提供无需登录即可访问的公开隐私政策页面：`/privacy-policy`。页面内容与后台“系统配置 -> 系统文章 -> 隐私协议”保持一致，可作为应用商店和其他外部渠道的隐私政策链接。

## 方案

新增一个独立于后台 `Layout` 的 Vue 路由和页面组件，并将 `/privacy-policy` 加入路由登录白名单。页面复用现有 `getSystemArticleByTypeApi(ArticleType.PRIVACY)` 接口读取公开数据，不新增或修改后端接口。

不采用后台 Layout 内页面，因为公开访问者不应看到后台导航；不采用静态 HTML，因为静态内容无法跟随后台编辑结果更新。

## 页面行为

- 浏览器标题为“隐私政策”。
- 首次进入时显示稳定尺寸的加载状态。
- 请求成功且存在内容时，渲染后台保存的 HTML 富文本，并显示最后更新时间。
- 接口返回空内容时，显示“隐私政策暂未发布”。
- 请求失败时，显示明确的失败状态和“重新加载”按钮。
- 页面兼容手机和桌面视口，正文保持适合长文阅读的宽度与行高。
- 富文本中的图片限制在正文宽度内，表格可横向滚动，长链接和长单词可以换行。

## 路由与数据流

1. 用户访问 Admin 域名的 `/#/privacy-policy`。
2. Vue Router 匹配公开常量路由，登录守卫通过白名单放行。
3. 页面请求公开接口 `GET /system-articles/privacy`。
4. 页面从统一响应的 `data` 中读取文章内容并渲染。

项目使用 hash 路由，因此最终外部链接格式是：

```text
https://<Admin 部署域名>/#/privacy-policy
```

## 安全边界

富文本内容由已登录后台管理员维护，沿用项目现有富文本信任边界。本次不改变 API 权限、数据库结构、共享响应协议或部署配置。

## 测试与验证

- 单元测试覆盖成功、空内容和请求失败三种状态。
- 路由检查覆盖 `/privacy-policy` 已注册且在未登录白名单中。
- 运行 Admin 定向测试、TypeScript 检查或构建。
- 启动本地 Admin 后，使用浏览器分别检查桌面和手机视口，确认无需登录、无内容重叠、加载和错误状态可用。
